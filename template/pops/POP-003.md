# POP-003: Autocorrecao de Erros

- **Trigger:** Qualquer erro, warning ou comportamento inesperado durante execucao
- **Autonomia:** Nivel 2 (auto-executar correcoes seguras) / Nivel 1 (apresentar opcoes para o resto)
- **Requer:** Nada

## Procedimento

1. **Detectar:** Verificar saida de todo comando. Distinguir warning (informativo) de erro (bloqueante)
2. **Diagnosticar:** Identificar causa raiz, nao apenas sintoma
3. **Classificar:** O agente pode resolver sozinho?

### Correcoes seguras (resolver sozinho):
- Erros de Git (case sensitivity, staging, line endings, merge simples)
- Arquivos recriaveis a partir do contexto
- Erros de sintaxe em arquivos que o agente criou
- Warnings que nao impedem operacao
- Conflitos de nomes/caminhos no filesystem
-> **Corrigir imediatamente, informar o que fez**

### Requer decisao humana (apresentar opcoes):
- Erros em dados de producao (banco, APIs ativas)
- Conflitos de merge com codigo de terceiros
- Falhas de credenciais ou permissoes
- Situacoes com 2+ caminhos validos e consequencias diferentes
- Causa raiz desconhecida
-> **Apresentar opcoes no formato padrao:**

```
PROBLEMA: [descricao clara]
CAUSA: [por que aconteceu]
OPCOES:
  A) [acao] — [consequencia]
  B) [acao] — [consequencia]
RECOMENDACAO: [opcao recomendada e por que]
```

## Anti-Loop

Se mesma correcao falhar 2x -> parar e apresentar opcoes ao usuario.
Nunca tentar a mesma solucao 3 vezes.

## Criterios de Sucesso

- Erro resolvido ou opcoes claras apresentadas
- Nunca ignorar erro silenciosamente
- Usuario informado do que aconteceu e do que foi feito

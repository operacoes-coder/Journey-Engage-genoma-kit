# POP-003: Autocorrecao de Erros

- **Trigger:** Qualquer erro, warning ou comportamento inesperado durante execucao
- **Autonomia:** Nivel 2 (auto-executar correcoes seguras) / Nivel 1 (apresentar opcoes)
- **Requer:** Nada

## Procedimento

### 1. Detectar
- Verificar saida de todo comando
- Distinguir warning (informativo) de erro (bloqueante)

### 2. Diagnosticar
- Identificar causa raiz, nao apenas sintoma
- Consultar `specs/error-taxonomy.md` se existir

### 3. Classificar

| Tipo | Risco | Acao |
|------|-------|------|
| Erro meu (typo, logica simples) | Baixo | Corrigir sozinho |
| Erro de config local | Baixo | Corrigir sozinho |
| Erro de Git (case, staging, merge simples) | Baixo | Corrigir sozinho |
| Warnings nao bloqueantes | Baixo | Informar e seguir |
| Erro que afeta dados | Alto | Perguntar ao usuario |
| Erro em producao | Critico | SEMPRE perguntar |
| Erro recorrente (3+ vezes) | Medio | Criar task + investigar |
| 2+ caminhos validos com consequencias | Medio | Apresentar opcoes |

### 4. Corrigir
- Se safe: corrigir automaticamente, informar o que fez
- Se risky: apresentar opcoes no formato:

```
PROBLEMA: [descricao clara]
CAUSA: [por que aconteceu]
OPCOES:
  A) [acao] — [consequencia]
  B) [acao] — [consequencia]
RECOMENDACAO: [opcao recomendada e por que]
```

### 5. Registrar
- Atualizar SNAPSHOT com o que aconteceu
- Se erro recorrente: criar task em `tasks/` para investigacao profunda
- Se erro grave: registrar no historico da sessao atual (`history/`)
- Se causou decisao: registrar em DECISIONS.md com timestamp

### 6. Prevenir
- Se padrao identificado: documentar em `docs/anti-patterns.md`
- Se fix nao obvio: documentar em `docs/post-mortems/`
- Se recorrente: adicionar a `specs/error-taxonomy.md`

## Anti-Loop

- Maximo 2 tentativas da mesma solucao
- Se falhar 2x → parar e apresentar opcoes ao usuario
- Nunca tentar a mesma solucao 3 vezes

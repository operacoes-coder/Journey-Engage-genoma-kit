# POP-001: Save de Fim de Sessao / Protecao Anti-Compressao

- **Trigger:** Qualquer um dos gatilhos abaixo (auto-executar IMEDIATAMENTE):
  1. Usuario encerra sessao ou muda de assunto
  2. **ALERTA AMARELO:** ~15 trocas de mensagens sem save
  3. **ALERTA LARANJA:** ~25 trocas OU 10+ arquivos lidos OU tarefa complexa concluida
  4. **ALERTA VERMELHO:** ~35 trocas OU sinal de compressao OU perda de contexto
  5. Sistema envia mensagem de compressao automatica (EXECUTAR IMEDIATAMENTE)
  6. Agente percebe que nao lembra detalhes anteriores da sessao
- **Autonomia:** Nivel 2 (auto-executar — NUNCA pedir permissao, NUNCA adiar)
- **REGRA CRITICA:** PRIORIDADE ABSOLUTA sobre qualquer tarefa em andamento.

## Procedimento

### Fase 1: Commitar Trabalho Pendente

1. `git status` → verificar mudancas nao commitadas
2. Commitar TUDO pendente com conventional format
3. Se houver conflitos: resolver primeiro

### Fase 2: Verificar Decisoes Pendentes

4. Revisar trabalho da sessao — houve decisoes nao registradas?
5. Verificar triggers de decisao (DECISIONS.md > Triggers de Analise)
6. Se sim: registrar em `DECISIONS.md` com timestamp real:
   - `date +%Y-%m-%d` para data
   - `date +%H:%M` para hora
7. Incluir rationale completo (POR QUE, nao so O QUE)

### Fase 3: Salvar Historico de Sessao

8. Obter timestamp real: `date +%Y-%m-%d-%H%M`
9. Criar `history/session-NNN-YYYY-MM-DD-HHmm.md` com template:
   - Horario de inicio e fim (reais do computador)
   - Tudo que foi concluido
   - Tasks pendentes (com referencia cruzada a tasks/)
   - Decisoes tomadas na sessao
   - Erros encontrados e resolucoes
   - Metricas (commits, arquivos, trocas ~estimadas)
   - Contexto completo para proxima sessao

### Fase 3.5: Capturar Aprendizados (rede de seguranca)

9b. Revisar a sessao: houve incidente com causa raiz cravada, premissa corrigida ou descoberta nao obvia que NAO foi capturada no momento (via POP-003)?
9c. Se sim, rodar `/session-learnings` para cada um — gera o MD de 9 campos em `learnings/` e destila a regra no `LEARNINGS.md`. Atencao especial aos campos forward-looking **8. Prevencao** e **9. Medidas de seguranca**.
9d. No `history/` da sessao, deixar so a referencia resumida (1 linha por aprendizado) apontando para o arquivo em `learnings/`.

> A captura IDEAL e no momento do aprendizado (POP-003); esta fase do POP-001 e a REDE DE SEGURANCA para nao perder nenhum no fim.

### Fase 4: Migrar Tasks Pendentes

10. Verificar tasks em `tasks/` com status DOING → mudar para TODO se nao concluidas
11. Tasks DONE → mover para secao "Concluidas"
12. Tasks novas identificadas durante sessao → criar em tasks/
13. Atualizar contagem e prioridades

### Fase 5: Atualizar SNAPSHOT

14. Atualizar `.context/SNAPSHOT.md` COMPLETO e AUTOCONTIDO:
    - Module Status atualizado
    - In Progress com estado real
    - Tasks Pendentes com referencia cruzada
    - Planos Ativos atualizados
    - Next Steps repriorizados
    - Context to Resume com:
      - DOING/BLOCKED_BY/NEXT_ACTION
      - LAST_SESSION com numero e timestamp
      - Decisoes tomadas (resumo)
      - Arquivos modificados
      - Erros resolvidos
      - Estado exato da tarefa (ex: "step 7 de 15")
    - Recent Activity com entrada desta sessao (data + hora)
15. SNAPSHOT deve ser AUTOCONTIDO — retomar SEM ler outros arquivos

### Fase 6: Commit de Sessao

16. `git add` todos os arquivos GENOMA alterados
17. `git commit -m "session(save): session NNN - [resumo] [AMARELO|LARANJA|VERMELHO]"`
18. Informar: "Checkpoint salvo. Contexto preservado."

## Niveis de Alerta

| Trocas | Nivel | Acao |
|--------|-------|------|
| ~15 | AMARELO | Avisar + executar |
| ~25 ou 10+ arquivos | LARANJA | Executar imediatamente |
| ~35 ou compressao | VERMELHO | EMERGENCIA — prioridade maxima |

## Criterios de Sucesso

- Zero mudancas nao commitadas
- SNAPSHOT atualizado e AUTOCONTIDO
- Historico de sessao salvo com timestamps reais
- Tasks migradas corretamente
- Decisoes registradas com rationale
- Proxima sessao retoma em ~3k tokens

# POP-001: Save de Fim de Sessao / Protecao Anti-Compressao

- **Trigger:** Qualquer um dos gatilhos abaixo (auto-executar IMEDIATAMENTE):
  1. Usuario encerra sessao ou muda de assunto
  2. **ALERTA AMARELO:** ~15 trocas de mensagens sem save
  3. **ALERTA LARANJA:** ~25 trocas OU 10+ arquivos lidos na sessao OU tarefa complexa concluida
  4. **ALERTA VERMELHO:** ~35 trocas OU sinal de compressao do sistema OU sensacao de perda de contexto
  5. Sistema envia mensagem de compressao automatica (EXECUTAR IMEDIATAMENTE)
  6. O agente percebe que nao lembra detalhes de algo discutido antes na sessao
- **Autonomia:** Nivel 2 (auto-executar — NUNCA pedir permissao, NUNCA adiar)
- **Requer:** Nada
- **REGRA CRITICA:** Este POP tem PRIORIDADE ABSOLUTA sobre qualquer tarefa em andamento.
  Se um gatilho disparar no meio de uma tarefa, PARAR a tarefa, executar POP-001, depois retomar.

## Procedimento

1. `git status` -> verificar mudancas nao commitadas
2. Commitar TUDO pendente com conventional format
3. Atualizar SNAPSHOT.md completo e AUTOCONTIDO:
   - `## Session` — Numero, data, ultimo commit hash
   - `## Module Status` — Cada modulo com status + % + detalhe do que falta
   - `## In Progress` — Checklist do que esta feito [x] e pendente [ ]
   - `## Next Steps` — Priorizado por urgencia > criticidade > dependencia
   - `## Context to Resume` — BLOCO CRITICO: tudo que o proximo agente precisa saber
     para retomar SEM precisar ler outros arquivos. Inclui:
     - O que estava sendo feito quando o save aconteceu
     - Decisoes tomadas nesta sessao (com justificativa resumida)
     - Arquivos modificados e o que mudou em cada um
     - Erros encontrados e como foram resolvidos
     - Estado exato da tarefa atual (ex: "no meio do step 7 de 15")
     - Comandos/queries que estavam funcionando (copiar literalmente)
     - Qualquer informacao que seria perdida pela compressao
   - `## Pending Triggers` — POPs que devem ser verificados
   - `## Recent Activity` — Ultimos commits com data e hash
4. Criar/atualizar historico de sessao (se o projeto usa historicos datados)
5. `git add` todos os arquivos alterados + .context/
6. `git commit -m "session(save): session NNN - [resumo] [AMARELO|LARANJA|VERMELHO]"`
7. Informar usuario: "Checkpoint salvo. [motivo]. Contexto preservado para continuidade."

## Criterios de Sucesso

- Zero mudancas nao commitadas
- SNAPSHOT atualizado e AUTOCONTIDO (ler sozinho = retomar 100%)
- Zero informacao perdida. Proximo agente retoma sem perguntar nada.
- Proxima sessao pode retomar em ~3k tokens

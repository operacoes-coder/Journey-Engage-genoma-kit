# POP-002: Checkpoint Mid-Session (Monitoramento Continuo)

- **Trigger:** O agente DEVE manter um contador mental de trocas e avaliar CONTINUAMENTE:
  - A cada ~8 trocas: "Preciso salvar algo?"
  - A cada arquivo grande lido: "Meu contexto esta crescendo"
  - A cada decisao tomada: "Isso precisa ser persistido?"
  - Ao receber resultado de API/query: "Isso e volatil, preciso salvar?"
  - >10 trocas sem save OU decisao significativa OU mudanca de assunto
- **Autonomia:** Nivel 2 (auto-executar quando necessario)
- **Requer:** Nada

## Modos

### LIGHT (~8 trocas, mudancas pequenas)
1. Atualizar SNAPSHOT.md "Context to Resume"
2. Commit: `checkpoint(light): [motivo]`

### FULL (~15 trocas, ou decisao importante)
1. Atualizar SNAPSHOT.md completo
2. DECISIONS.md se houve decisao nao registrada
3. Verificar tasks em andamento → atualizar status
4. Commit: `checkpoint(full): [motivo]`

### SAFETY (antes de acao arriscada OU ~25 trocas)
1. Executar POP-001 completo (save de sessao)
2. Criar save point git com hash registrado
3. Commit: `snapshot(safety): save point before [acao]`

## Escalacao Automatica

- Se LIGHT nao suficiente e contexto crescendo → escalar para FULL
- Se FULL nao suficiente → escalar para POP-001 completo
- Na duvida, SEMPRE escalar para cima (salvar demais > salvar de menos)

## Criterios de Sucesso

- Contexto importante preservado
- Commit com mensagem descritiva
- Nenhuma informacao critica perdida entre checkpoints

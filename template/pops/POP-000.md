# POP-000: Diagnostico de Inicio de Sessao

- **Trigger:** Inicio de toda sessao (automatico — NAO esperar usuario pedir)
- **Autonomia:** Nivel 2 (auto-executar SEMPRE)
- **Requer:** Nada (leitura de .context/, history/, tasks/, plans/, git)
- **Deteccao:** Primeira mensagem, entrada na pasta do projeto, "pop 000", "onde paramos"

## Procedimento

### Fase 1: Carregar Contexto (~1 min)

1. Ler `CLAUDE.md` → regras e estrutura do projeto
2. Ler `.context/SNAPSHOT.md` → estado atual completo
3. Ler `specs/glossary.md` → linguagem do dominio (se existir)
4. `git log --oneline -10` → timeline recente
5. `git status` → mudancas nao commitadas
6. Se `.env` existe → ler credenciais → verificar MANIFEST

### Fase 2: Verificar Tasks Pendentes (~1 min)

7. Ler `tasks/` → buscar tasks com status TODO ou DOING
8. Contar tasks pendentes por prioridade (URGENTE > ALTA > MEDIA > BAIXA)
9. Identificar tasks BLOCKED → verificar se desbloquearam
10. Tasks DOING sem sessao ativa → marcar como TODO

### Fase 3: Verificar Planos Ativos (~30s)

11. Ler `plans/` → buscar planos com status "Em Execucao" ou "Aprovado"
12. Verificar proxima fase/step pendente de cada plano
13. Identificar dependencias entre planos

### Fase 4: Verificar Historico (~30s)

14. Ler ultima sessao em `history/` → o que foi feito, o que ficou pendente
15. Verificar continuidade (pendencias da ultima sessao = prioridade)
16. Verificar triggers temporais de outros POPs

### Fase 5: Verificar Ferramentas (~30s)

17. Verificar `tools/` → configs validas
18. Se `.mcp.json` existe → MCP servers configurados
19. Verificar credenciais necessarias para tasks pendentes

### Fase 6: Gerar Diagnostico Proativo

20. **Gerar relatorio proativo baseado no projeto:**
    - Analisar TODAS as informacoes coletadas
    - Identificar o que e CRITICO, ATRASADO, BLOQUEADO
    - Priorizar por: urgencia > criticidade > dependencias > impacto
    - Incluir proximos passos concretos e acionaveis
    - Referenciar tasks/planos relevantes
    - Adaptar formato ao estado real (sem template fixo)
21. Apresentar ao usuario
22. Perguntar: "Qual sera o foco desta sessao?"

## Output Esperado

```
=== POP-000 | Diagnostico de Sessao ===
Projeto: [nome] | Sessao: [N] | [data hora real]

Estado: [OK/ATENCAO/CRITICO]
Ultima sessao: [data hora] — [resumo]

Tasks: X pendentes (Y urgentes, Z bloqueadas)
Planos: X ativos (fase atual de cada)
Tools: X/Y configuradas

Prioridades:
1. [URGENTE] ...
2. [IMPORTANTE] ...
3. [PROXIMO] ...

Qual sera o foco desta sessao?
```

## Criterios de Sucesso

- Diagnostico inteligente apresentado, adaptado ao projeto
- Tasks pendentes identificadas e priorizadas
- Planos ativos com fase atual indicada
- Usuario sabe exatamente onde retomar e o que e prioritario
- Timestamps reais do computador
